# Wallet and Funding

This page explains what PolyTrade controls, how to deposit safely, and what the app does not provide.

## The short version

- PolyTrade creates a signer and stores its private key encrypted so the service can place trades without asking you to sign each order. **This is custodial.**
- Start only from [@cpolytrade_bot](https://t.me/cpolytrade_bot), create the wallet in the Telegram Mini App, and back up the signer key offline.
- Deposit only with an asset/network route displayed in **User**, and send a small test first.
- PolyTrade does not expose a withdrawal API or in-app withdrawal workflow.
- PolyTrade does not automatically redeem resolved winnings.

A wallet address, visible balance, or successful deposit does not remove market, custody, smart-contract, infrastructure, or total-loss risk.

## What wallet do I receive?

Each user receives:

- a signer generated by PolyTrade;
- an encrypted signer private key;
- a public account address; and
- in the intended gasless mode, a separate Polymarket deposit/funder wallet.

The backend decrypts the signer when it needs to sign unattended orders. This convenience creates custody risk: compromise of the application or of both the database and encryption secret can put wallets at risk.

With all Builder credentials configured, PolyTrade creates the gasless wallet through Polymarket's relayer, waits for indexing, and attempts exchange approvals. Normal setup and trading should not require user-funded MATIC.

Wallet creation can return before every upstream readiness check succeeds. An address appearing is not proof that trading is ready.

## Deposit safely

1. Open **User** in the Telegram Mini App.
2. Request deposit addresses.
3. Select an asset/network combination that is explicitly displayed as supported.
4. Compare the complete destination address before sending.
5. Send a small test amount.
6. Wait for conversion and indexing.
7. Verify the cash balance before sending more.

The Bridge API may provide EVM, Solana, Bitcoin, and Tron address families. An address family does not mean every token on that network is supported.

### Avoid irreversible mistakes

- Never infer support from address format alone.
- Never send a token or use a network that is not displayed for that route.
- Do not copy a deposit address from logs, old screenshots, or another user.
- Keep the source transaction hash.
- Stop and investigate if the test deposit does not appear.

Blockchain transfers generally cannot be reversed. PolyTrade cannot guarantee recovery of funds sent with the wrong asset, network, or address.

## Understand the balances

- **Cash:** available collateral reported for the wallet.
- **Position value:** current estimated value of open holdings.
- **Claimable:** resolved winning value that has not been redeemed.
- **Equity:** combined account value.

Conversion, public indexing, and displayed values can lag. These balances are operational views, not audited statements. If values disagree, compare the source transaction and live wallet state before attempting another transfer or trade.

## Withdrawals and direct control

PolyTrade does not expose a withdrawal API or in-app withdrawal workflow. Do not assume that a cash balance can be transferred out inside PolyTrade.

Users who need direct control can export the signer private key after fresh Telegram verification and use compatible external tools. Before doing so, understand that the signer and gasless deposit/funder wallet may differ. An exported key is a permanent secret; anyone who obtains it may control the signer, and PolyTrade cannot rotate or revoke a copied key.

## Back up the signer key

Private-key export requires:

- a valid session;
- a linked Telegram identity; and
- fresh Telegram Mini App data no older than five minutes.

Store the key offline in a secure vault. Screenshots, clipboard history, browser extensions, cloud backups, chat messages, and support tickets are common exposure paths. PolyTrade staff do not need your private key, session cookie, or Telegram launch data to troubleshoot a public transaction.

## Resolution is not redemption

When a market resolves, a winning position can become claimable. PolyTrade records claimable value, but it does not approve the auto-redeem operator and does not automatically redeem winnings.

Redeem through Polymarket when needed. A position can appear **Closed** while value is still claimable.

## What pausing does

Pausing the account, disabling a followed source, or unfollowing blocks new buys. It does not sell existing positions or redeem resolved winnings. Existing positions still need monitoring through sale, resolution, and any required redemption.

## Technical wallet modes

The intended production path uses configured Polymarket Builder credentials and the gasless relayer. Without Builder credentials, the signer is also the trading EOA and can require MATIC for one-time USDC approvals. That fallback is not the intended production consumer setup.

Operators should use the [Operators hub](operators.md) for configuration, deployment, monitoring, and recovery guidance.
