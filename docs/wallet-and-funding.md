# Wallet and Funding

## Wallet model

Each user receives a signer generated by PolyTrade, an encrypted private key, a public account address, and—in gasless mode—a separate Polymarket deposit/funder wallet.

The backend signs orders for unattended copying. This is custodial operation.

## Gasless wallet path

With all Builder credentials configured, PolyTrade creates the wallet through Polymarket's relayer, waits for indexing, and attempts exchange approvals. Normal setup and trading should not require user-funded MATIC.

Wallet creation can return before every upstream readiness check succeeds. If funds are visible but orders fail for allowance/readiness reasons, pause and escalate.

## EOA fallback

Without Builder credentials, the signer is also the trading wallet. This path can require MATIC for one-time USDC approval and is not the intended production mode.

## Deposit funds

1. Open **User**.
2. Request deposit addresses.
3. Select a displayed supported asset/network route.
4. Send a small test amount.
5. Wait for conversion and indexing.
6. Verify cash before sending more.

The Bridge API may return EVM, Solana, Bitcoin, and Tron address families. An address family does not mean every token on that network is supported.

## Deposit safety

- Never infer the network from address format alone.
- Never send an unsupported token.
- Do not reuse an address from logs or another user.
- Confirm full address, network, and asset.
- Start with a test deposit.
- Keep the source transaction hash.

PolyTrade cannot reverse a transfer or guarantee recovery from the wrong network or asset.

## Balances

- **Cash:** available collateral reported for the wallet.
- **Position value:** current value of open holdings.
- **Claimable:** resolved winning value not yet redeemed.
- **Equity:** combined account value.

Public indexing can lag. If values disagree, compare the public transaction, live wallet state, and PolyTrade database before correcting anything.

## Withdrawals

PolyTrade does not expose a withdrawal API or in-app withdrawal workflow. Do not document or promise one.

Users needing direct control can export the signer private key after fresh Telegram verification and use compatible external tools. Understand the gasless wallet/funder relationship first.

## Private-key export

Export requires a valid session, linked Telegram identity, and Telegram Mini App data no older than five minutes.

The raw key is returned to the client. Anyone who sees it can control the signer, and PolyTrade cannot rotate or revoke it. Screenshots, clipboard history, browser extensions, and chat backups are exposure paths.

## Resolution and redemption

PolyTrade detects resolved positions and includes claimable value in the account. It does not approve the auto-redeem operator and does not automatically redeem winnings.

Redeem through Polymarket when needed. A position may appear Closed while value remains claimable.

## Recovery boundaries

The operator cannot reverse confirmed blockchain transfers, recover a key that was never backed up and can no longer be decrypted, guarantee unsupported-deposit recovery, or act without valid wallet authority.
