PolyTrade — production workflow

Telegram access → leader detection → risk transaction → real FOK order → durable recovery

Fast path — responsiveness

  • The detector checks followed leaders every 2 seconds.
  • Fresh BUYs and SELLs are deduplicated and converted into immediate intents.
  • It never bypasses the shared risk gate or final wallet verification.

Reconciler — correctness

  • Every 5 seconds it compares real leader positions with durable copy rows.
  • It opens, resizes, closes or resolves; resizing requires more than 25% drift.
  • Paused follows cannot grow, but reductions, exits and resolutions continue.

Risk transaction — authorization

  • Both entry paths converge on one transaction-protected BUY gate.
  • All 11 user controls are reloaded and enforced under the user lock.
  • A unique durable claim reserves risk capacity and prevents duplicate orders.

Execution — real money

  • The system checks the current wallet, book depth, minimum size, price band and slippage.
  • It signs a protected fill-or-kill order: complete fill or cancellation.
  • There is no paper-mode branch in the copy execution module.

Persistence — durable truth

  • Positions, trade events, claims, settings and sessions live in Postgres.
  • The actual Polymarket wallet remains the financial truth used for safety checks.
  • Telegram success alerts are sent only after the confirmed result commits.

Recovery — fail safely

  • An ambiguous network outcome becomes uncertain, not an automatic retry.
  • The reconciler later checks the real wallet and adopts the fill or releases the claim.
  • Only one production copy worker runs, avoiding cross-process duplicate execution.
